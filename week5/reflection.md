# INFOMAN1 Week 5 Lab - Reflection

A SELECT statement belongs to Data Query Language (DQL) and only retrieves information from a database without altering anything. In contrast, Data Definition Language (DDL) commands such as DROP and ALTER change or remove table structures, while Data Manipulation Language (DML) commands such as INSERT, UPDATE, and DELETE add, modify, or erase stored rows. Because SELECT is strictly read-only, it cannot accidentally corrupt records or break a table design, making it safe to run freely while exploring a database.

In Task 4, I intentionally removed the single quotes around the date filter. Working query: SELECT appointment_id, appointment_date, reason_for_visit FROM appointment WHERE appointment_date >= '2026-09-01'; Faulty query: SELECT appointment_id, appointment_date, reason_for_visit FROM appointment WHERE appointment_date >= 2026-09-01;. Instead of throwing a syntax error, MySQL returned all five appointments, including two August visits, along with one warning. Comparing both results and running SHOW WARNINGS; revealed Warning 1292: Incorrect datetime value: '2016', showing that unquoted 2026-09-01 was evaluated as subtraction (2016) rather than a date literal.
